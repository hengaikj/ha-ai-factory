# HA AI Software Factory UX/UI 设计规格

文档编号：UXUI-HA-F00-001  
状态：Design Gate 已批准（2026-09-23）
产品依据：`docs/product/prd.md`（产品负责人已确认，2026-09-23）  
视觉方向：项目台账（方向 1）

## 设计目标

为项目负责人和 Orchestrator 提供一个可快速浏览多个并行项目、识别 Gate 状态和 Open Issues、进入项目详情的桌面 Web 总览页。页面首屏优先呈现项目组合与待处理状态，保持工程流程信息可追溯；Agent Runtime 作为受授权的工作入口呈现，不承担 Gate 批准。

## 页面说明

### 页面一：项目总览（主页面）

- **全局侧边栏**：展示智行官彩色品牌标志和六个 MVP 导航入口：项目、任务、交付物、Gate、Open Issues、Agent Runtime。当前页面“项目”使用品牌蓝高亮。
- **页面头部**：显示“项目”标题、项目搜索入口和“创建项目”主操作。认证、通知和用户菜单的具体行为受 OI-002/配置约束，不在本阶段定义。
- **项目表格**：表格为页面主要内容，列出项目名称/描述、负责人、当前阶段、Gate 状态、Open Issues 数量和更新时间。项目行可进入项目详情；不同项目的数据必须清晰区分。
- **状态表达**：当前阶段使用浅蓝标签；Gate 已通过使用绿色状态；待评审使用琥珀色状态；阻塞或未通过使用红色状态。颜色同时配合文字，不能只依赖颜色传达状态。
- **最近活动**：在项目表格旁或下方提供紧凑活动列表，显示项目、对象、操作者、时间和动作。活动只服务于阶段追踪，不扩展为独立分析仪表盘。
- **空态与错误态**：无项目时显示创建项目引导；搜索无结果时显示清除搜索入口；加载失败时显示重试和错误说明；数据权限不足时显示无权访问提示。

### 页面二：项目详情（从项目行进入）

- 顶部显示项目名称、负责人、当前阶段和 Gate 总状态。
- 主区域显示生命周期阶段、未完成任务、交付物和 Open Issues 的关联摘要。
- 右侧或抽屉显示最近状态变更和证据引用入口。
- 仅允许进入已授权项目；项目切换不能混淆任务、交付物和 Gate 上下文。

### 页面三：Agent Runtime 执行入口

- 从任务或项目详情进入 Agent Runtime 执行面板。
- 执行前显示项目、任务、模型、工具和权限摘要；未批准配置必须阻止启动并明确提示 OI-003。
- 执行中显示排队、执行中、成功、失败、取消等状态；结果回写到项目和任务上下文。
- 页面不提供 Gate 批准操作；Reviewer 独立性和角色兼任边界按 OI-004 在权限设计中落实。

## 组件说明

| 组件 | 用途 | 关键交互 |
| --- | --- | --- |
| BrandMark | 展示智行官主品牌图形与文字标志。 | 点击返回项目总览；不改变原始标志比例和颜色。 |
| SideNavigation | 访问六个 MVP 模块。 | 当前项高亮；无权限项显示不可用状态或隐藏，规则待 OI-004。 |
| PageHeader | 展示标题、搜索和主操作。 | 搜索项目名称；创建项目进入表单。 |
| ProjectTable | 展示并行项目及其状态。 | 行点击进入详情；列状态提供文字和颜色；支持空态、加载态、错误态。 |
| StatusTag | 展示阶段、Gate、Open Issues 状态。 | 颜色与文字组合；阻塞/待评审状态可进入对应处理页。 |
| ActivityList | 展示关键状态变更。 | 查看对象上下文和证据引用；不直接修改 Gate 结果。 |
| ProjectDetailDrawer | 快速查看项目摘要。 | 展示项目、阶段、任务、交付物、Open Issues 和最近变更。 |
| AgentRunPanel | 配置并查看 Agent 执行。 | 执行前校验授权；执行中轮询或订阅状态；结束后展示结果。 |
| EvidenceLink | 关联交付物、Gate 和评审证据。 | 打开来源文件或证据详情；来源权威规则受 OI-005 约束。 |

## 交互与状态说明

### 页面状态

| 状态 | 表现 | 用户动作 |
| --- | --- | --- |
| 初始加载 | 表格骨架和导航保持稳定。 | 等待数据返回。 |
| 有数据 | 展示项目表格和活动列表。 | 搜索、打开项目、创建项目。 |
| 无数据 | 显示“暂无项目”和创建项目主操作。 | 创建项目。 |
| 搜索无结果 | 保留搜索词并显示清除入口。 | 修改或清除搜索。 |
| 请求失败 | 显示错误原因和重试操作。 | 重试或返回。 |
| 无权限 | 隐藏敏感数据或展示无权访问。 | 联系管理员；具体权限由 OI-004 决定。 |

### Gate 与评审状态

- `待评审`：显示琥珀色标签，可进入评审详情；不显示为已批准。
- `已通过`：显示绿色标签，并允许进入依赖该 Gate 的下一阶段。
- `已退回` / `阻塞`：显示红色标签，展示原因、关联 Open Issues 和下一步处理动作。
- `HUMAN_DECISION_REQUIRED`：显示人工决策标识；未决时不允许相关 Gate 被标记为通过。

### Agent Runtime 状态

- `待启动`：展示已分配任务和授权摘要，启动按钮仅在 OI-003 配置已批准时可用。
- `排队中`：显示提交时间和取消入口。
- `执行中`：显示执行阶段和最近事件；不允许修改运行中的授权范围。
- `成功`：展示结果、关联项目/任务和证据引用入口。
- `失败`：展示可读错误、重试条件和人工处理入口；不自动扩大权限。
- `取消`：保留取消人、时间和已产生的结果摘要。

## MVP 操作流程

以下流程补齐 AT-02 至 AT-07 的可完成操作。每个流程均从侧边栏、项目详情或相关对象进入，完成后在当前对象和活动记录中显示结果。

| 验收场景 | 操作入口 | 操作步骤 | 完成后的可见结果 |
| --- | --- | --- | --- |
| AT-02 阶段与任务跟踪 | 项目详情 → 任务区 → 新建任务 | 选择项目和阶段，填写任务说明，选择责任角色，关联交付物，保存；在任务详情选择状态并提交。 | 任务详情显示责任角色、阶段、状态和关联交付物；项目概览的未完成任务计数同步更新；活动列表记录创建或状态变化。 |
| AT-03 交付物评审 | 任务详情 → 交付物 → 提交评审；Reviewer 从交付物列表进入 | 打开交付物，查看版本和说明，选择通过/退回/待澄清，填写评审说明并关联证据，提交结论。 | 交付物显示结论、Reviewer、时间、说明和证据；退回/待澄清状态提供重新提交入口，并且不显示为已批准。 |
| AT-04 Gate 检查 | 项目详情 → Gate → 进入待审 Gate | 逐项打开检查项，选择通过/不通过/待澄清，填写说明并关联交付物或证据；全部检查项完成后提交 Gate 结论。 | Gate 显示检查项完成度和结论；未通过或待澄清时显示阻塞原因和处理入口；通过后才出现“推进阶段”操作。 |
| AT-05 人工决策项 | 项目详情 → Open Issues → 新建事项 | 填写问题、影响、决策角色，标记 `HUMAN_DECISION_REQUIRED`，提交；决策者打开事项，填写决定并选择已决定/继续跟踪，提交。 | Open Issue 显示责任角色、状态、决定记录和影响；未决事项显示阻塞提示，关联 Gate 不可提交为已通过。 |
| AT-06 模板与规则 | 侧边栏 → 交付物 → 模板与规则 | 按项目或阶段筛选，打开条目查看内容和版本，选择查看来源或下载；对缺失条目显示补充来源入口。 | 条目显示项目、阶段、版本和来源；查看/下载动作写入活动记录；来源不明时显示待确认标识，不伪装为正式模板。 |
| AT-07 状态审计 | 项目详情 → 活动与审计；对象详情 → 查看变更 | 按对象类型或时间筛选，打开一条变更记录，查看变更前后状态、操作者、时间、说明和证据链接。 | 审计详情可追溯到项目、任务、交付物或 Gate；返回原对象时保留筛选上下文；审计记录只读。 |

### Runtime 配置拒绝流程

Agent Runtime 执行面板必须在启动前完成配置检查，并将拒绝原因和下一步动作放在启动区域内。

| 配置状态 | 启动按钮 | 页面提示 | 下一步动作 |
| --- | --- | --- | --- |
| 未配置 | 禁用 | “无法启动：尚未配置模型、工具或执行权限。” | “查看配置要求”打开配置清单；“创建 Open Issue”登记 OI-003。 |
| 待批准 | 禁用 | “无法启动：执行配置等待批准。当前配置不能产生外部副作用。” | “查看待决事项”进入 `HUMAN_DECISION_REQUIRED` 记录；“返回任务”继续处理非执行工作。 |
| 已拒绝/已过期 | 禁用 | “无法启动：授权已拒绝或过期。” | “查看拒绝原因”查看 Reviewer/决策记录；“重新提交配置”进入人工决策流程。 |
| 已批准 | 可用 | “配置已批准，可启动执行。” | 点击“启动执行”；启动后进入排队中。 |
| 校验失败 | 禁用 | “无法启动：授权校验失败，请稍后重试或联系管理员。” | “重试校验”；仍失败时“创建 Open Issue”。 |

拒绝状态需同时展示项目、任务、模型、工具和权限摘要，防止用户误以为只缺少某个字段。页面不得提供绕过校验的按钮，也不得自动替换模型或扩大工具权限。

## 视觉规则

- 品牌主色：以智行官标志蓝为主色（参考 `#2F6FE8`）；琥珀色用于待评审，青色用于 Agent 执行中，绿色用于通过，红色用于阻塞。
- 页面底色使用浅灰白，内容区域以白色为主；用间距和分隔线建立层级，减少装饰性阴影。
- 桌面基准视口：1440 × 1024；侧边栏约 220px，主内容区采用宽表格布局。
- 中文界面优先；阶段名称可使用项目生命周期中的英文原名并配中文说明。
- 所有状态必须同时提供文字、图标或结构信息，满足非色觉用户识别。

## API 绑定（待 Contract 阶段批准）

本节只定义页面需要的数据关系，不批准接口路径、请求方法或字段命名。Contract 未批准前不得修改代码接口。

| 页面/组件 | 所需数据 | 绑定说明 |
| --- | --- | --- |
| ProjectTable | 项目列表、负责人、阶段、Gate 状态、Open Issues 数量、更新时间 | 必须带项目标识，避免并行项目数据串联。 |
| ProjectDetailDrawer | 项目摘要、任务、交付物、Open Issues、状态变更、证据 | 所有关联对象应能追溯到项目标识。 |
| Gate 状态 | Gate 检查项、结论、Reviewer、时间、证据 | Gate 通过由独立 Reviewer 产生；Orchestrator 和 Agent 不得代批。 |
| ActivityList | 变更对象、前后状态、操作者、时间、说明 | 用于审计阶段推进依据。 |
| AgentRunPanel | 项目/任务标识、授权模型、工具、执行状态、结果、错误 | OI-003 关闭前不得启用真实执行；未批准操作必须在服务端拦截。 |
| EvidenceLink | 交付物、Gate、文件或证据引用 | 权威来源和版本规则由 OI-005 在后续确认。 |

## Design Gate 前置事项

1. 产品负责人已确认 PRD，UX/UI 方向已选择“项目台账”。
2. OI-004 必须在权限设计中落实 Reviewer 独立性和角色兼任边界。
3. OI-003 必须在启用 Agent Runtime 执行前关闭；本设计只展示授权校验和状态，不代表已启用真实执行。
4. 需要独立 Designer/Reviewer 审查页面信息层级、状态可识别性、错误/空态和资源使用，再决定 Design Gate 是否通过。
