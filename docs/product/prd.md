# HA AI Software Factory 产品需求文档

文档编号：PRD-HA-F00-001
状态：产品负责人已确认（2026-09-23）
依据：`docs/requirement/requirement-baseline.md`（REQ-HA-F00-001，Requirement Gate 已批准）

## 产品目标

为多个并行 AI 软件项目提供一个可追踪的工程流程工作台。项目负责人和工程角色能够围绕项目阶段、任务、交付物、Gate、待决事项和 Agent 执行结果协作，并能追溯阶段推进所依据的评审结论与证据。

产品遵循以下原则：

1. 阶段按已批准的生命周期顺序推进，未通过的 Gate 不得被任务状态或 Agent 执行结果替代。
2. 人工评审和决策保留明确责任人及记录；Agent 不自动批准 Requirement、Design、Contract、Review 或 Release Gate。
3. 项目、任务、交付物、Gate、Open Issue 和 Agent 执行结果保持可关联、可追溯。
4. Agent 只能执行已批准的模型、工具和操作；未批准或超出授权范围的操作不得启动。
5. 本产品只管理软件工程流程，不承诺替代通用代码托管、CI/CD、云运维或完整业务系统生成平台。

## 用户

| 用户 | 需要完成的工作 | 主要关注 |
| --- | --- | --- |
| 项目负责人 / 需求提出者 | 创建项目、维护目标和约束、确认需求范围、处理待决事项。 | 多项目清晰可分、范围和决策可追溯。 |
| Orchestrator | 维护阶段与任务状态、协调工程 Agent、跟踪交付物及门禁准备情况。 | 任务责任明确、门禁状态可靠、待决事项可见。 |
| 工程 Agent | 根据分配任务产出交付物，必要时通过 Agent Runtime 执行已授权工作。 | 任务上下文充分、执行范围明确、结果能关联回项目与任务。 |
| Reviewer / Gate 审核者 | 独立检查交付物和证据，记录通过、退回或待澄清结论。 | 评审责任独立、依据完整、结论可审计。 |
| 项目管理员 | 管理项目成员及项目级配置。 | 项目边界和成员配置明确；具体权限规则待 OI-004 决策。 |

权限模型、角色兼任规则、身份认证和组织边界仍受 OI-002、OI-004、OI-008 约束。本 PRD 不预设具体认证方式或权限矩阵。

## MVP 功能列表

以下功能均属于已批准的 Requirement MVP 范围，按 MVP 必需（P0）管理。具体交互在 UX/UI 阶段定义，接口与数据契约在 Contract 阶段定义。

| 编号 | 功能 | 产品要求 | 关联验收场景 |
| --- | --- | --- | --- |
| P-01 | 多项目管理 | 创建、查看多个项目；每个项目记录名称、目标、技术栈、当前阶段和负责人；项目数据彼此可区分。 | AT-01 |
| P-02 | 生命周期与任务跟踪 | 展示项目当前阶段、Gate 状态和未完成任务；创建、分配、更新任务并关联说明、责任角色和交付物。 | AT-02 |
| P-03 | 交付物评审 | 管理阶段交付物及其通过、退回、待澄清结论，记录 Reviewer、时间和证据引用。 | AT-03 |
| P-04 | Gate 检查与阶段约束 | 按检查项记录 Gate 结果、审核人、时间和证据；未通过 Gate 时阻止依赖该 Gate 的阶段推进。 | AT-04 |
| P-05 | Open Issues 与人工决策 | 记录问题、影响、责任决策角色、处理状态和决定；支持标记 `HUMAN_DECISION_REQUIRED`。 | AT-05 |
| P-06 | 模板与规则索引 | 展示项目采用的模板和规则，支持查看或下载并保留来源引用。 | AT-06 |
| P-07 | 状态审计 | 记录并展示项目、任务和 Gate 的关键状态变更，包括变更前后状态、操作者、时间和关联说明。 | AT-07 |
| P-08 | Agent Runtime 执行 | 提供 Python/FastAPI Runtime，按项目任务调用 Agent，返回并关联执行状态和结果；仅执行已批准的模型、工具及操作。 | AT-08；受 OI-003 限制 |

### 明确不属于 MVP 的能力

- 自动批准任何阶段 Gate，或绕过未批准的 API、数据、安全契约。
- 通用代码托管、CI/CD、云资源编排、生产运维、模型训练、微调或通用模型托管。
- 组织级租户隔离、复杂组织层级、计费、客户门户、移动端和高级报表。
- 未经项目负责人和相应权限责任人批准的模型调用、工具操作或外部副作用。

部署、认证、权限、模型与工具供应商、非功能指标、交付物权威来源及发布规则仍按 Open Issues 管理，不在本 PRD 中臆定。

## 用户故事

### US-01：分别管理并行项目

作为项目负责人，我希望创建并查看多个项目，以便并行推进不同 AI 软件项目并区分各自的负责人、技术栈、阶段和状态。

- 创建两个项目后，列表中可分别找到并打开它们。
- 修改一个项目的信息或阶段状态，不改变另一个项目的数据。
- 项目详情能展示该项目的名称、技术栈、负责人、当前阶段和 Gate 状态。

### US-02：掌握阶段和任务进度

作为 Orchestrator，我希望在项目上下文中查看阶段、Gate 和任务，并分配责任角色，以便协调工作并识别未完成事项。

- 项目概览显示当前阶段、Gate 状态及未完成任务。
- 任务可关联任务说明、责任角色和交付物。
- 更新任务后，任务详情和项目概览中的状态保持一致。

### US-03：提交并评审阶段交付物

作为工程 Agent，我希望将交付物关联到阶段并提交评审，以便 Reviewer 能在明确上下文中作出结论。

- Reviewer 可记录通过、退回或待澄清结论，并提供说明和证据引用。
- 交付物显示结论、Reviewer 和评审时间。
- 退回或待澄清的交付物不得显示为已批准。

### US-04：依据 Gate 推进阶段

作为 Reviewer，我希望按检查项检查阶段交付物并记录证据，以便阶段推进有明确且可审计的依据。

- Gate 记录包含检查项、结论、Reviewer、时间和证据引用。
- Gate 未通过时，依赖该 Gate 的阶段不能推进。
- 仅在 Gate 获批后，项目才可以进入依赖该 Gate 的后续阶段。
- Orchestrator 或 Agent 不能代替 Reviewer 批准自己的评审。

### US-05：跟踪待决事项

作为项目负责人，我希望看到尚未解决的问题、其影响和决策责任人，以便在阻塞阶段推进前安排决策。

- Open Issue 可记录问题、影响、建议决策角色和当前状态。
- 需要人工判断的事项可标记 `HUMAN_DECISION_REQUIRED`。
- 决策记录包含决定内容及处理状态；未决事项不得显示为已解决。

### US-06：查找项目模板和规则

作为工程 Agent，我希望查看或下载项目采用的模板和规则，以便按项目约束提交一致的交付物。

- 模板/规则索引能定位到对应内容。
- 查看或下载的条目能追溯到项目采用的来源。

### US-07：审计阶段和状态变更

作为 Reviewer，我希望按时间查看项目、任务或 Gate 的状态变更，以便核实变更经过及阶段推进依据。

- 记录展示变更对象、变更前后状态、操作者、时间和关联说明。
- 可从 Gate 结论追溯到相关检查项和证据引用。

### US-08：通过 Agent Runtime 执行获批任务

作为 Orchestrator，我希望通过 Agent Runtime 对已分配任务发起执行并查看结果，以便让授权的 Agent 工作与项目进度保持关联。

- 执行记录关联项目和任务，展示执行状态及结果。
- 运行前需存在已批准的模型、工具和操作权限配置。
- 未获批准或超出权限范围的操作不得执行；Agent 不能批准 Gate。
- OI-003 须在 Agent Runtime 执行功能启用前关闭。

## 验收标准

PRD 产品评审至少确认以下内容：

1. P-01 至 P-08 与已批准 Requirement Baseline 的 MVP 范围一致，未隐含新增项目能力。
2. US-01 至 US-08 均有可检查的验收条件，并分别映射到 AT-01 至 AT-08。
3. 未通过 Gate 不能推进依赖阶段；人工 Reviewer 的独立性不被 Agent 或 Orchestrator 绕过。
4. Agent Runtime 仅执行已批准的模型、工具和操作；启用执行前关闭 OI-003。
5. OI-004 在权限设计中明确 Reviewer 独立性和角色兼任边界；认证、组织隔离、交付物来源和非功能指标继续作为 Open Issues，不被误写成已批准产品行为。
6. 非 MVP 项未被纳入 P0 范围；后续 UX/UI、Design Handoff 和 Contract 阶段分别形成其所需交付物与批准记录。

本 PRD 已由产品负责人确认，可作为 UX/UI 阶段输入；不据此批准接口、数据模型或开发工作。
